# Version tracking

Binspector follows [Semantic Versioning 2.0.0](https://semver.org/spec/v2.0.0.html).
This file records what changed at each version and why, so the reasoning behind a
version bump does not live only in commit messages.

## Roadmap

| Version | Scope | State |
|---|---|---|
| 3.0.0 | Correctness: boundary matching, container unpacking, confidence scoring, all output formats, color and accessibility | released |
| 3.1.0 | peframe capability mirror: PE parsing, sections and entropy, imports, resources, Authenticode, packer heuristics, IoC extraction | planned |
| 3.2.0 | Reputation lookups (VirusTotal, MetaDefender, hash only) and CVE enrichment via NVD | planned |
| 3.3.0 | Fuzzing: self-fuzzing harnesses, parser-differential mode, external engine orchestration | planned |

## 3.0.0

**Bump reason:** MAJOR. Two changes break the 2.0.0 contract:

1. Matching is now case insensitive by default, where 2.0.0 was case sensitive, so an
   unchanged invocation can return different results.
2. The no-op `fuzz` subcommand placeholder was removed, so `binspector fuzz` is now read
   as a request to scan a file named `fuzz`.

Separately, results change substantially even where flags did not, because 2.0.0
reported false positives and missed real findings. Any stored baseline must be redone.
Every other 2.0.0 flag still works, with `--ignore-case` and `--json` kept as deprecated
aliases that warn rather than fail.

### Why this release exists

2.0.0 did not work. Verified against a real scan of
`SampleApp_1.0.0_x64.msixbundle` for
an internal tracking ticket:

- All 3 reported findings were false positives. `gets` matched `targetsize`,
  `system` matched `System` and `FileSystem` and `CustomSystemFont`.
- Real coverage was zero. `strcpy`, `strcat`, `sprintf`, `memcpy`, `printf`, and
  `malloc` each returned 0 occurrences in a 256MB Windows application, which is
  impossible. The `.msixbundle` is a ZIP, so the scan only ever saw compressed bytes.

### Measured result on the same sample

| Metric | 2.0.0 | 3.0.0 |
|---|---:|---:|
| Members scanned | 1 | 2,967 |
| Strings extracted | 3,150,271 | 6,555,762 |
| Distinct functions reported | 3 (all false) | 39 |
| Occurrences reported | 398 (all false) | 306 |
| Occurrences suppressed as low confidence | n/a | 24,205 |
| Executable images reached | 0 | many (PE) |
| Runtime | not comparable | 4.2 s |

Offsets were then verified against the real bytes: 65 sampled hits across both ASCII
and UTF-16LE landed exactly on the reported token, with 0 mismatches.

### Changed

- Matching is case insensitive by default. `--case-sensitive` selects the opposite.
- CSV output no longer requires `--matches-only`.
- Reported offsets point at the matched token, not at the containing string.
- Default output is a summary. A full per-string dump requires `--dump`.

### Deprecated

- `--ignore-case`: now the default, accepted with a warning so existing command lines
  keep working.
- `--json`: use `--format json`.
- The no-op `fuzz` subcommand placeholder was removed. Real fuzzing lands in 3.3.0.
